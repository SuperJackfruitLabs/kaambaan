# Two modes implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restructure `apps/web` into three routed destinations — Plan, Operate, Workspace — so
that every surface is reachable on a phone, every control is focusable and tappable, and the board
stops asserting things it cannot know.

**Architecture:** SvelteKit SPA (`ssr=false`, `prerender=false`, `adapter-static` with an
`index.html` fallback), so new routes resolve client-side and need no Worker change. A shell
layout owns navigation and the board header; each destination is a route beneath it. State stays
in `app.svelte.ts`, minus the `Screen` union, which routing replaces.

**Tech Stack:** Svelte 5 runes, Tailwind v4, vitest + `@cloudflare/vitest-pool-workers` (api),
plain vitest (web), Playwright (e2e).

**Spec:** `docs/superpowers/specs/2026-09-03-two-modes-design.md`

## Global Constraints

- **No API, Durable Object or schema change.** If a screen appears to need one, stop and raise it.
- **Baseline is green:** contract 63, api 525, web 41. Run `pnpm -r test` before every commit, and
  `pnpm --filter @kaambaan/web e2e` before finishing a slice.
- **The e2e suite is the only guard on navigation.** Where it asserts on a structure a task
  changes, update the assertion **in the same commit** as the change. Never delete an e2e test to
  make a change pass.
- **One breakpoint: 900px, mobile-first, `min-[900px]:` only.** Never pair with `max-[900px]:` —
  Tailwind's `max-` is exclusive and the pair leaves 900px matching both.
- **Keep the tokens.** `--ink --surface --inset --line --text --muted --marigold --live --coral
  --accent-bg` keep their names and values. Both themes stay.
- **No surface is removed before its replacement exists.** The agents modal survives until Task 14.
- Comments explain WHY, at the density of the surrounding files.

  +layout.svelte                                  shell: rail | bottom nav | header | <slot>

### Task 1: The two system tokens, and one focus rule

**Files:** Modify `apps/web/src/app.css`

- [ ] **Step 1: Add the tokens beside the existing ones**

```css
/* WCAG 2.2 target size, and the focus treatment applied once for the whole app. Both were
   missing entirely: computed outline-style was `none` on every button and card tile, and eight
   controls sat under 24px — including the two added for accessibility. */
:root {
  --focus: 2px solid var(--marigold);
  --focus-offset: 2px;
  --tap: 24px;
}
@media (pointer: coarse) { :root { --tap: 44px; } }
```

- [ ] **Step 2: One rule, at the root, not per component**

```css
@layer base {
  :focus-visible {
    outline: var(--focus);
    outline-offset: var(--focus-offset);
    border-radius: 6px;
  }
}
```

- [ ] **Step 3:** Add a `.tap` utility (`min-width/min-height: var(--tap)`) for controls whose
      glyph must stay small — pad the hit area, never enlarge the glyph.
- [ ] **Step 4:** `pnpm -r test`, commit.

### Task 2: The acceptance criteria, as an e2e spec that fails first

**Files:** Create `apps/web/e2e/reachable.spec.ts`

- [ ] **Step 1: Write it, and run it to watch it fail**

Assert at 390×844 and 1440×900, on each destination:

```ts
// no element past the right edge, and the page does not scroll sideways
expect(await page.evaluate(() => document.documentElement.scrollWidth)).toBe(390);
const past = await page.evaluate(() => [...document.querySelectorAll('*')]
  .filter((el) => el.getBoundingClientRect().right > window.innerWidth + 1).length);
expect(past).toBe(0);

// every interactive target meets the floor
const small = await page.evaluate(() => [...document.querySelectorAll('button,a,input,select,[role="button"]')]
  .map((el) => el.getBoundingClientRect())
  .filter((r) => r.width > 0 && r.height > 0 && (r.width < 24 || r.height < 24)).length);
expect(small).toBe(0);

// focus is visible on a card
await page.keyboard.press('Tab');
expect(await page.evaluate(() => getComputedStyle(document.activeElement!).outlineStyle)).not.toBe('none');
```

- [ ] **Step 2:** Expected: fails on overflow (7 controls) and on target size (8 controls).
- [ ] **Step 3:** Commit the failing spec — it is the definition of done for this slice.

## Self-review

- **Spec coverage:** §5 shell → Tasks 3–5; §6 Plan → 6–9; §7 Operate → 10–12; §8 Workspace →
  13–14; §9 system → 1–2; §4 routes → 3, 13, 15. §11's slice order is the task order.
- **Ordering:** Task 2's e2e spec fails until Task 3 (overflow) and Task 7 (target size), which is
  intended — it is the slice's definition of done, committed red on purpose.
- **Interfaces:** Task 4 deletes `Screen`/`setScreen`; Tasks 10–12 consume `app.needsYou()` as
  extended in Task 10. Task 11 moves the budget dialog, which Task 15 must therefore not re-add.
- **Residual:** `apps/web` has no component render harness, so Tasks 6–9 and 13–15 are covered by
  e2e and by eye rather than by unit tests. Recorded rather than pretended otherwise.
